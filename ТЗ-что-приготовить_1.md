# Промт для Claude Code: приложение «Что приготовить?»

Скопируй текст ниже целиком в Claude Code, запустив его в пустой папке проекта.

---

Создай PWA-приложение «Что приготовить?» — подбор рецептов по бюджету для рынка СНГ (цены в рублях). Пользователь вводит сумму денег и получает варианты блюд, которые может приготовить на эти деньги.

## Стек и требования к проекту

- React 18 + Vite, JavaScript (не TypeScript).
- PWA: manifest.json, service worker (vite-plugin-pwa), полная работа офлайн после первой загрузки.
- Никакого бэкенда. Все данные — статичные JSON в проекте, пользовательские данные — в localStorage.
- Дизайн mobile-first (основная аудитория — телефоны), но корректно на десктопе.
- Язык интерфейса — русский.
- Деплой планируется на GitHub Pages: настрой `base` в vite.config под подпапку репозитория, добавь npm-скрипт деплоя.
- Позже приложение будет обёрнуто в TWA для Google Play — учитывай: никаких зависимостей от специфичных браузерных API, всё должно работать в Chrome Android.

## Структура данных

Создай два JSON-файла в `src/data/`:

### products.json — база продуктов
```json
{
  "id": "grechka",
  "name": "Гречка",
  "unit": "г",
  "packSize": 900,
  "packPrice": 95,
  "category": "крупы"
}
```
- `unit`: "г", "мл" или "шт".
- `packSize`/`packPrice` — размер и цена типичной упаковки в магазине (средняя цена по СНГ).
- Заполни базу минимум 60 базовыми продуктами с реалистичными средними ценами для России 2026 года: крупы, макароны, мясо (курица, свинина, говядина, фарш), рыба (минтай, горбуша консерв.), яйца, молочка (молоко, сметана, творог, сыр, масло сливочное), овощи (картофель, лук, морковь, капуста, помидоры, огурцы, свёкла, чеснок), масло растительное, мука, сахар, соль, специи базовые, хлеб, томатная паста, майонез, зелень.

### recipes.json — база рецептов
```json
{
  "id": "grechka-s-kuricej",
  "name": "Гречка с курицей",
  "mealType": ["обед", "ужин"],
  "timeMinutes": 40,
  "servings": 2,
  "calories": 520,
  "ingredients": [
    { "productId": "grechka", "amount": 200 },
    { "productId": "kurica-file", "amount": 300 },
    { "productId": "luk", "amount": 80 },
    { "productId": "maslo-rast", "amount": 20 }
  ],
  "steps": ["...", "..."]
}
```
- `calories` — на одну порцию, примерно.
- `mealType`: массив из "завтрак" / "обед" / "ужин" / "перекус".
- Заполни базу 40 реальными рецептами простой домашней кухни СНГ (гречка/макароны/картошка с мясом, супы — борщ, куриный, гороховый; омлеты, сырники, оладьи, плов, тушёная капуста, котлеты, салаты и т.п.) с реалистичными граммовками и понятными шагами приготовления. Распредели по типам приёмов пищи. Позже база будет расширяться — код не должен зависеть от количества рецептов.

## Логика расчёта цен (критично важно)

Для каждого рецепта считай ДВЕ цифры:

1. **Стоимость порции** — пропорциональная: для каждого ингредиента `(amount / packSize) * packPrice`, суммировать, разделить на `servings`. Показывается как «порция ~85 ₽».
2. **Стоимость закупки с нуля** — сколько реально потратишь в магазине: для каждого ингредиента, которого НЕТ в списке «есть дома», считается стоимость целых упаковок: `ceil(amount / packSize) * packPrice`. Показывается как «закупка ~240 ₽».

Подбор по бюджету по умолчанию фильтрует по стоимости порции, но в настройках/переключателе на главном экране можно переключить режим на «закупка с нуля» — тогда фильтрация идёт по второй цифре. Оба числа всегда видны на карточке рецепта.

## Пользовательские цены

- В любом рецепте каждая строка ингредиента редактируема: тап по цене → инпут → пользовательская цена упаковки сохраняется в localStorage и с этого момента используется во ВСЕХ расчётах вместо средней.
- Отдельный экран «Продукты и цены»: полный список продуктов, поиск, редактирование цены каждого, кнопка «сбросить к средней» у изменённых.
- Визуальная маркировка: если все ингредиенты рецепта имеют пользовательские цены — расчёт помечается «по вашим ценам» (зелёный бейдж), иначе «цены примерные» (серый бейдж).
- На главном экране мелкий дисклеймер: «Цены средние по сетевым магазинам и могут отличаться от вашего магазина. Вы можете указать свои цены.»

## Фича «Есть дома»

- Экран со списком всех продуктов и чекбоксами «есть дома». Сохраняется в localStorage.
- Продукты, отмеченные как имеющиеся, исключаются из «стоимости закупки» (но НЕ из стоимости порции).
- На карточке рецепта недостающие продукты визуально выделены в списке ингредиентов.
- Соль, специи, масло в количествах до 20 г/мл считай «копеечными»: их можно по умолчанию включить в «есть дома», но пользователь может снять галочку.

## Главный экран (ядро приложения)

1. Крупное поле «Ваш бюджет, ₽» (числовая клавиатура на мобильном: inputmode="numeric").
2. Переключатель типа приёма пищи: Все / Завтрак / Обед / Ужин / Перекус.
3. Фильтры (сворачиваемые): время готовки (до 20 / до 40 / до 60 мин / любое), режим расчёта (порция / закупка с нуля).
4. Сортировка выдачи: «Сытнее за эти деньги» (калории на рубль, по умолчанию), «Ближе к бюджету», «Быстрее приготовить», «Дешевле».
5. Лента карточек: название, фото-заглушка или эмодзи блюда, «порция ~85 ₽ · закупка ~240 ₽», время, калории, сердечко избранного.
6. Пустой бюджет = показать все рецепты. Если под бюджет ничего не подходит — дружелюбное сообщение и ближайший по цене рецепт как предложение.
7. Результаты пересчитываются мгновенно при изменении бюджета/фильтров (всё на клиенте).

## Экран рецепта

- Название, время, порции, калории, оба варианта стоимости с бейджем точности цен.
- Список ингредиентов: граммовка, цена (редактируемая), маркер «нет дома» для недостающих.
- Шаги приготовления.
- Кнопки: «В избранное», «Добавить в список покупок» (добавляет недостающие продукты).

## Избранное и список покупок

- Избранное: отдельный экран, хранение в localStorage, сердечко на карточках.
- Список покупок: агрегирует недостающие ингредиенты из добавленных рецептов (один продукт из двух рецептов = одна строка с суммарным количеством и количеством упаковок), чекбоксы «куплено», итоговая сумма внизу, кнопка очистки. Хранение в localStorage.

## Навигация

Нижний таб-бар (мобильный паттерн): Подбор / Избранное / Список покупок / Есть дома / Цены.

## Темы оформления

- Светлая и тёмная тема. Все цвета — через CSS-переменные (custom properties) на :root и [data-theme="dark"], никаких захардкоженных цветов в компонентах.
- По умолчанию тема берётся из системной настройки (prefers-color-scheme).
- Переключатель темы (системная / светлая / тёмная) — иконка в шапке главного экрана. Выбор сохраняется в localStorage и имеет приоритет над системной настройкой.
- В manifest.json и meta theme-color учесть обе темы, чтобы статус-бар в TWA/PWA соответствовал теме.
- Проверить контрастность текста и бейджей в обеих темах.

## Что НЕ делать

- Не подключать никакие внешние API и парсеры цен.
- Не добавлять регистрацию, аккаунты, аналитику.
- Не использовать localStorage-обёртки с побочными эффектами — простые JSON.parse/stringify с try/catch.
- Не усложнять: никакого Redux, только useState/useContext.

## Порядок работы

1. Каркас проекта, роутинг, таб-бар, PWA-конфиг.
2. products.json и recipes.json с полным контентом.
3. Модуль расчёта цен (отдельный файл `src/lib/pricing.js` с чистыми функциями + краткие комментарии) — стоимость порции, стоимость закупки, учёт пользовательских цен и «есть дома».
4. Главный экран с подбором, фильтрами, сортировкой.
5. Экран рецепта с редактированием цен.
6. «Есть дома», Избранное, Список покупок, экран «Продукты и цены».
7. Проверь: смена цены пользователем мгновенно меняет расчёты во всех экранах; офлайн-режим работает; `npm run build` собирается без ошибок.
